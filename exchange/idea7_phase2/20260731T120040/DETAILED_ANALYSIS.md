### 1. 验证集完全没有提升

```

```

**现象**: Val Recall 从第一个 epoch 就固定在 0.3224，100 个 epoch 完全没有变化。

**这意味着什么？**
- 模型在验证集上的预测从未改变
- 学到的权重对验证集没有任何帮助
- 可能陷入了某个局部最优点

### 2. 训练集 Recall 也很低

```
Train Recall 范围: 0.12 - 0.20 (平均 ~0.15)
Baseline (QORE): 0.4454
```

**现象**: 训练集 Recall 只有 0.15，远低于 baseline 的 0.4454。

**这意味着什么？**
- 模型连训练数据都没学好（欠拟合）
- 不是过拟合问题（过拟合会是 train high, val low）
- 模型容量不足或优化困难

### 3. 权重学习不稳定

```
w_a 范围: 1.4 - 3.1 (波动大)
w_b: 始终 = 1.0 (完全不变)
```

**现象**: 
- w_a 波动很大，没有收敛
- w_b 始终不变，优化器没有更新它

**这意味着什么？**
- w_b 的梯度可能为 0 或很小
- 冗余项可能对损失没有影响
- 只优化质量权重不够

### 4. Loss 几乎不变

```
Loss 范围: 0.890 - 0.896
变化幅度: < 1%
```

**现象**: Loss 在很小的范围内波动，没有下降趋势。

**这意味着什么？**
- 优化停滞
- 梯度可能很小
- 学习率可能太小，或任务太难

## 💡 根本原因分析

### 假设 1: K=5 选择太难 🔥 **最可能**

**问题**: 从 50 个候选中用 soft 方式选择 K=5，梯度信号太弱。

**证据**:
- Gumbel-Softmax 在 K << N 时梯度稀疏
- K=5 out of 50 = 10% 选择率，大部分候选的梯度接近 0
- MVP 用的是 K=5 out of 10 = 50%，成功了

**类比**: 
- 简单：从 10 个苹果中选 5 个最好的（50% 选择率）
- 困难：从 50 个苹果中选 5 个最好的（10% 选择率）

### 假设 2: 特征信号不足

**问题**: 只用 cosine similarity 作为质量信号，可能不够。

**证据**:
- QORE 用的是 DPR score（预训练的相关性）
- Soft QUBO 只能优化权重，不能学习新特征
- 如果 DPR embedding 本身质量就不高，优化权重帮不上忙

### 假设 3: Soft QUBO 架构限制

**问题**: 可微分 QUBO 可能不是学习子集选择的最佳方法。

**证据**:
- QUBO 是组合优化问题，松弛后损失了离散性
- Gumbel-Softmax 的温度退火可能破坏了学习
- 可能需要更直接的选择机制（如 attention）
