# DEUT-VLM 吐血版跑图像跑视频完整流程

### 一、 租用 GPU 配置要求（你要花钱租什么型号？）

Qwen2.5-VL-7B 是一个 70 亿参数的视觉语言模型，本身加载就需要比较大的显存。

*   **显卡 (GPU)**：**最低24GB显存**。推荐租用单张 **RTX 3090 (24G可能会爆，还是更高更好)** 或者 **RTX 4090 (24G)**。如果预算充足且需要跑视频或大批量数据，选择 **A100 (40G)** 最稳。
*   **系统内存 (RAM)**：至少 32GB 以上（推荐 64GB，有的平台默认内存够用）。
*   **磁盘空间**：至少 100GB (模型权重下载就要约 15-20GB，加上环境需要预留充足空间)。
*   **基础环境**：在平台（比如AutoDL、趋动云、恒源云等）选机器时，**强烈建议镜像选择装有：Jittor：Ubuntu20.04, Python 3.10, Pytorch 2.4.0, CUDA 11.8, cuDNN 8, NVCC, VNC, Jittor**（下载对应版本的[ `flash-attn`](https://github.com/Dao-AILab/flash-attention/releases/download/v2.7.3/flash_attn-2.7.3+cu11torch2.4cxx11abiFALSE-cp310-cp310-linux_x86_64.whl) ）。

### 二、 傻瓜式环境配置与运行步骤

当你租好了服务器，打开它的终端（Terminal）页面后，直接按照以下顺序一条条复制并在终端回车执行。

#### 1. 设置网络加速（国内服务器必备）
如果你租的是国内服务器，连 HuggingFace 下载模型会很慢，先粘贴这句把网络切换成镜像站：
```bash
export HF_ENDPOINT=https://hf-mirror.com
pip config set global.index-url https://pypi.tuna.tsinghua.edu.cn/simple
```

#### 2. 创建并激活虚拟环境（并强制对齐PyTorch与CUDA版本）
保证环境干净，避免跟别的项目冲突，**并且提前安装好匹配的基础库防止后续报错**：
```bash
conda create -n myconda python=3.10 -y
conda activate myconda

# 【避坑关键】主动指定安装和机器 CUDA 11.8 强制匹配的 PyTorch 2.4.0 版本，防止跑后面 setup.py 时系统乱装最新版导致的 flash-attn 编译报错：
pip install torch==2.4.0 torchvision==0.19.0 torchaudio==2.4.0 --index-url https://download.pytorch.org/whl/cu118
```

#### 3. 下载该项目代码并进入目录
*(提示：如果你直接在之前打开工作区的本地环境跑，可以跳过git clone，直接进入DUET-VLM目录即可，但这里假设你在云端全新的环境)*
```bash
git clone https://github.com/AMD-AGI/DUET-VLM.git
cd DUET-VLM
```

#### 4. 一键安装依赖关系
这里带上 `[qwen]` 标签，脚本会自动帮你安装Qwen依赖（重点！这一步需要一点时间）：
```bash
# 不要一键安装，直接

```
再补齐项目中要求的最新的transformers版本和计算加速包：

torch                    2.4.0+cu118
torchaudio               2.4.0+cu118


### 三、 跑通 Qwen2.5-VL + DUET 推理

配置好之后，我们找一张图片来见证奇迹。

#### 1. 准备一张测试图片
你可以随便弄一张图片上传到这台虚拟机的 `DUET-VLM` 文件夹里，并且把它的名字改成 `test.jpg` 备用。如果你不会上传，终端里运行这句代码现场下载一只猫咪的图：
```bash
wget https://images.unsplash.com/photo-1514888286974-6c03e2ca1dba -O test.jpg
sudo apt update
sudo apt install imagemagick
convert test.jpg -resize 256x256 test_small.jpg
```
然后为了不爆显存，把这个test.jpg缩小一点变成test_small.jpg

#### 2. 跑通基础的 Qwen（不开加速）
进入 Qwen 测试目录，然后运行。
```bash
cd qwen2_5_vl

python run_inference.py \
    --model-path ~/Desktop/DUET-VLM/qwen2_5_vl/qwen2.5-vl-7b \
    --image ../test_small.jpg \
    --query "Please describe what is in this image in detail." \
    --bf16
```



只要输出了一段关于这张图的描述，说明你的底层模型已经彻底跑通了！

#### 3. 体验 DUET-VLM 特效（开启 论文中的超级加速）
根据论文给出的超参数，一键复制粘贴以下带大量参数的命令，跑通完整的 Dual-Stage Token Reduction (第一级视觉Token聚合缩减 + 第二级大语言模型内层级丢弃)：
```bash
python run_inference.py \
    --model-path ~/Desktop/DUET-VLM/qwen2_5_vl/qwen2.5-vl-7b \
    --image ../test_small.jpg \
    --query "Please describe what is in this image in detail." \
    --bf16 \
    --visionzip \
    --dominant 0.65 \
    --contextual 0.05 \
    --pdrop \
    --layer-list "[7,14,21]" \
    --ratio-list "[0.75,0.5,0.25]"
```

一定要加--bf16 \（使用 Bfloat16 (bf16) 数据类型进行训练的，不然会出现全是addCriterion乱码）

# 跑视频需要修复代码

## 问题分析

在 DUET 模式下，`self.visual` 返回的是一个元组 `(hidden_states, attn_mean, attn_key)`：
- 图像处理代码正确解包：`image_embeds, attn_logits, attn_key = self.visual(...)`
- 视频处理代码没有解包：`video_embeds = self.visual(...)`，导致 `video_embeds` 实际上是元组而不是张量

## 修复内容

将第 2324 行从：
```python
video_embeds = self.visual(pixel_values_videos, grid_thw=video_grid_thw)
```

改为：
```python
video_embeds, _, _ = self.visual(pixel_values_videos, grid_thw=video_grid_thw)
```
（本地文件夹已修复）
