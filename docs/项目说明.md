# QORE 项目说明

你已经跑过 DUET-VLM 的代码，它的核心创新点是token 压缩。QORE 这个项目跟 DUET 没有代码上的继承关系，是完全新写的，但核心压缩思路有关联——子集筛选。区别在于我们要换应用场景和子集选择的方法。

---

## 项目概述

简单来说，LLM 推理的时候，上下文信息过多（KV cache 不够，或 RAG 检索回来太多段落放不进 context window）。需要从 N 个候选里选 K 个留下来。

现有方法（H2O、SnapKV、MMR 等）都采用贪心的方式选——按分数排序取 top-K。问题是：两个分数都很高但内容几乎一样的东西，贪心会把它俩都选上，浪费了一个名额。

本项目的做法是把选择问题写成一个 QUBO（二次无约束二值优化），用模拟退火/QAOA来解。QUBO 的好处是能同时考虑"单个项的质量"和"两两之间的冗余"，全局最优而不是贪心。

---

## 和 DUET-VLM 的关系

| | DUET-VLM | QORE |
|---|---------|------|
| 解决的问题 | VLM 里视觉 token 太多 | LLM 里上下文信息太多 |
| 选择什么 | 图像 patch token | KV-Cache entries / RAG 段落 |
| 怎么选 | 贪心 top-K | QUBO 优化（质量 + 冗余一起考虑）|
| 代码关系 | — | 完全独立，零继承 |

因此，数学上是同一个问题的不同实例，但工程实现和应用场景完全不一样。

## 数学公式

目标函数：

```
min E(x) = -Σ aᵢxᵢ + γ·Σ bᵢⱼxᵢxⱼ + λ(Σxᵢ - K)²

xᵢ ∈ {0,1}  选还是不选
aᵢ           质量分（越大越该留）
bᵢⱼ          i和j的冗余度（越大越不该同时留）
K            预算
λ            约束惩罚权重
γ            冗余项权重（代码里自动调的）
```

标准 QUBO 形式，可直接给量子退火器或 QAOA 线路跑。

---

## 两个应用场景

**RAG 段落选择**：检索到 100 个段落，context window 只能放 5-10 个。用 QORE 选出来的比 top-K 和 MMR 覆盖面更广（不会把名额浪费在说同一件事的重复段落上）。

**KV-Cache 驱逐**：长文本生成的时候 cache 满了，要决定丢哪些旧 token。现有方法按"被关注程度"排序丢，我们额外考虑 key 向量的相似度——两个 key 很像的 entry 只需要留一个。

---

## 量子的部分

与DUET 的最大区别——本项目的主 pipeline 是量子的。

核心设计：一个**参数化量子线路 U(h; θ)** 同时产出两个信号：

```
token 特征 hᵢ
      │
      ▼
  U(hᵢ; θ) 编码线路（可训练参数 θ）
      │              │
      ▼              ▼
  测量 ⟨Z⟩          态之间求 fidelity
      │              │
      ▼              ▼
  aᵢ (质量分)       bᵢⱼ (冗余度)
      │
      ▼
  构建 QUBO → 求解 → 输出 keep/drop
```

同一个量子线路跑一次，测量值反映出每个 token 的重要程度（a_i），两个 token 对应量子态的重叠度，反映出二者的冗余程度（b_ij）。通过一个统一的量子表示自然地给出两种信息。

求解器包括QAOA 和模拟退火。

量子部分基于三个框架实现：Qiskit、PennyLane、TensorCircuit。跑实验的时候默认用 TensorCircuit（最快），ablation 里对比三个框架的一致性。

## 代码结构

```
QORE-VLM/
├── qore/                    ← 核心框架
│   ├── qubo.py              # QUBO 矩阵构建
│   ├── signals.py           # 经典冗余度计算（cosine/RBF，作为 baseline）
│   ├── vqc/                 # 量子编码器（核心创新点）
│   │   ├── encoder.py       # U(h;θ) 线路，产出 a_i + b_ij
│   │   ├── scorer.py        # 统一接口：encode → QUBO → solve 
│   │   └── train.py         # parameter-shift 训练
│   ├── solvers/             # SA / QAOA×3 / greedy / brute
│   └── kernels/             # quantum kernel×3（独立的 b_ij 计算，用于ablation ）
│
├── applications/
│   ├── rag/                 ← 跑 RAG 实验
│   │   ├── selector.py      # select_passages(method="qore"|"vqc"|"topk"|"mmr")
│   │   └── baselines/       # top-K, MMR
│   └── kv_cache/            ← 跑 KV-Cache 实验
│       ├── qore_cache.py    # QORECache，直接当 past_key_values 传
│       └── baselines/       # H2O, Random, Window
│
├── scripts/                 ← 跑实验的脚本
│   ├── rag/run_nq.sh
│   ├── kv_cache/run_longbench.sh
│   └── ablations/run_all.sh
│
├── docs/
│   └── experiment_guide.md  ← 操作手册，包含详细步骤
│
└── results/                 ← 实验结果提交到这个目录
    └── _TEMPLATE/           # 复制一份改个名，按格式填
```

## 工作流程

### 1. 配环境

```bash
git clone https://github.com/tivilou/QORE-VLM.git
cd QORE-VLM
pip install dwave-neal dimod
pip install pennylane tensorcircuit qiskit qiskit-algorithms qiskit-optimization
pip install torch transformers datasets accelerate sentence-transformers faiss-gpu

# 跑一下测试确认装对了
python -m pytest qore/tests/ applications/ -q
# 应该看到 "91 passed"
```

### 2. 数据准备

不需要手动下载。所有数据集通过 HuggingFace `datasets` 在脚本里自动加载，第一次跑会下载到本地缓存。

**RAG 实验**：QA 数据（NQ、HotpotQA）+ 段落语料库（`facebook/wiki_dpr`，21M Wikipedia passages + DPR embedding）都是自动拉取。语料库约 35GB，第一次下载耗时较长，之后走缓存。

**KV-Cache 实验**：LongBench 和 PG-19。注意 LongBench 在较新版本的 `datasets` 库（≥4.0）上有加载兼容性问题（旧式 loading script 不再支持），如果遇到报错，降级到 `datasets==2.18` 可以解决。

### 3. 跑实验

优先级：

1. `bash scripts/rag/run_nq.sh` — Natural Questions 上的 RAG 实验
2. `DATASET=hotpotqa bash scripts/rag/run_nq.sh` — HotpotQA
3. `bash scripts/kv_cache/run_longbench.sh` — KV-Cache 在 LongBench 上
4. `bash scripts/ablations/run_all.sh` — 消融

前三个跑完就够写论文 experiments section 了。具体的模型下载、数据准备、参数怎么覆盖，都写在 `docs/experiment_guide.md` 里了。

### 输出文件说明

脚本跑完后自动产出结果文件，不需要手动整理。以 RAG NQ 实验为例，输出在 `results/rag/nq/`：

```
results/rag/nq/
├── qore.json      # QORE 方法的结果（经典信号 + SA求解）
├── vqc.json       # VQC 方法的结果（量子信号 + SA求解）
├── topk.json      # Top-K baseline
├── mmr.json       # MMR baseline
├── summary.csv    # 所有方法的对比表（自动生成）
├── train_log.json # VQC encoder 训练 loss 记录
└── vqc_encoder.npz # 训练好的 VQC 参数（可复用）
```

KV-Cache 实验类似，多了 h2o/window/random/full 几个策略文件。

每个 JSON 包含三部分内容：

- `config`：实验参数（模型、K、solver、seed 等），用于复现
- `metrics`：实验指标（见下表）
- `compression`：压缩效率指标

各场景的指标：

| 指标 | RAG | KV-Cache | 含义 |
|------|-----|----------|------|
| accuracy / F1 | ✓ | ✓ | 下游任务质量 |
| recall@K | ✓ | — | 选出的段落中包含 gold passage 的比例 |
| redundancy_ratio | ✓ | — | 选出段落间的平均相似度（越低越好） |
| diversity_score | ✓ | — | 1 - redundancy_ratio |
| perplexity | — | ✓ | 生成质量 |
| compression_ratio | ✓ | ✓ | K/N，实际保留比例 |
| tokens_kept | ✓ | ✓ | 保留的 token/passage 数 |
| tokens_total | ✓ | ✓ | 总候选数 |
| memory_saved_MB | — | ✓ | KV-Cache 节省的显存 |
| throughput_tok_per_sec | — | ✓ | 生成吞吐量（对比有/无 eviction）|
| solve_time_ms | ✓ | ✓ | QORE 求解耗时 |

训练日志 `train_log.json` 记录 VQC encoder 的训练过程（每步 loss），可以画 loss curve。VQC 训练在正式评测前完成，训练好的参数会保存下来供评测加载。

`summary.csv` 是所有方法指标的横向对比，直接可以用来画论文表格。

### 4. 提交结果

```bash
cp -r results/_TEMPLATE results/Bootrear_2026-07-XX
# 把跑出来的 json/csv 放进对应子目录
# 填一下 README.md 和 env.md（硬件、软件版本）
git add results/Bootrear_2026-07-XX/
git commit -m "exp: Bootrear — RAG + KV-Cache results"
git push origin main
```
