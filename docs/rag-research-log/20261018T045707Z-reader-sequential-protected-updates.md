# Reader 连续保护更新：训练边界可以累积，但量子尚未胜出

## 这轮想回答什么

上一轮只证明了一件很小的事：在固定 59 道训练题上，量子和经典 Reader 头都至少存在一次“救回一个漏选证据、同时不丢已有证据”的共享参数更新。它没有回答这种效果能否连续积累，也没有保证第一次救回的段落在下一次更新后仍然保留。

本轮因此只检验一个机制问题：每接受一次真实有效的更新后，重新计算当前边界，并把此前救回的候选加入保护集合；在固定预算内，能否继续救回第二个、第三个候选，而不以遗忘旧证据为代价。

## 实验怎样运行

- 只使用已经冻结的 59 道训练题、183 个原有保护成员和 135 个可救援候选。
- 量子头和参数量匹配的经典头都从恒等/初始状态出发；候选顺序在开始前固定。
- 每一步重新计算全部 59 题、每题 50 段的精确局部 Jacobian，求一个共享的有界参数更新。
- 线性规划给出的方向不能直接算成功。必须把更新放回真实 float32 Reader 头，对全部 59 题重新前向；只有救援数严格增加，且原有保护成员和之前救回的成员都不丢失，才接受这一步。
- 最多接受 3 步。没有打开 100 题评估标签或 87 题验证字段，也没有运行检索、Generator 或答案评测。

## 结果

| 分支 | 救援轨迹 | 最终救回 | 原有保护损失 | 已救回再丢失 | 候选尝试数 |
|---|---:|---:|---:|---:|---:|
| 量子初始头 | 0 → 1 → 2 → 3 | 3 | 0 | 0 | 8 |
| 匹配经典初始头 | 0 → 1 → 2 → 3 | 3 | 0 | 0 | 5 |

两个分支前两步救回的是相同训练案例：`training_002` 的候选 8 和 `training_048` 的候选 48。第三步开始分化：量子分支在第 8 个固定候选处救回 `training_004` 的候选 1；经典分支在第 5 个候选处就救回 `training_040` 的候选 2。

独立审计没有复用主运行器的通过标志，而是重新计算了 2 个初始基线和 27 次全 59 题真实前向。6 次接受和 21 次拒绝全部与主 trace 一致；378 个分离数值数组的形状、类型和哈希也全部通过。完整 274 MB 证据包已上传到 `five_ideas/reader_sequential_protected_updates/20261018T045707538341Z`。

## 这说明什么

正向结论是明确的：上一轮的一次安全更新不是只能偶然救回一个近边界样本。只要在每一步重新线性化，并把已经救回的候选纳入后续保护，训练集上的安全改善可以连续累积。这也再次说明，平均软损失不是合适的保护方式；离散 Top5 成员约束和真实全题前向门是关键。

但量子结论也同样明确：当前实验没有显示量子优势。量子和经典最后都救回 3 个，经典还用更少的候选尝试达到相同数量。两种几何确实在第三步选择了不同案例，但“路径不同”不等于“量子更好”。因此本轮等级仍是 L0 机制诊断，不能升级到 L1，更不能作为 L2 或论文效果。

## 从所有既往尝试累积出的判断

过去多轮 RAG 结果反复暴露两个问题：一是用 EM/F1 会混入检索和 Generator 的误差，不能准确判断 Top50→Top5；二是只优化平均分、排序代理或线性近似，经常会用丢失已有证据换取局部收益。Silver/三模型案例分析把评价目标改到了正确的 Top5 成员，本轮则进一步证明了“显式成员保护 + 真实前向接受”确实能解决训练阶段的遗忘问题。

当前最大的不确定性已经从“能不能在训练题上找到连续安全方向”转成“这种方向是否学到了可迁移规律，还是只记住了 59 道题的边界”。继续在同一批 59 题上把救援数从 3 提到更多，科研价值很低，也很容易把拟合能力误当成方法提升。

## 最优下一步

下一步应建立一个预先冻结的未见问题门：参数更新仍只由训练 59 题产生；训练结束后一次性在完全未参与候选选择、步长选择和停止判断的问题上，比较恒等 Reader、量子更新头和匹配经典头的直接/有用证据 Top5 成员变化。

成功门槛应至少包括：未见问题上的成员指标为正、原有正确成员不退化、结果不是少数问题偶然驱动。若要推进量子主张，还必须在同预算下超过经典对照及其不确定性；否则只能保留为经典可复现的保护更新机制。若未见问题没有收益，应停止这一训练目标，而不是回头用评估题调候选顺序或半径。
