# Reader Top-5 成员资格训练：独立对照实验交接

本轮把已经通过 CPU 审计的新训练目标接入独立实验。目的是检验：在不改变量子头容量和训练题目的情况下，让训练直接关心“证据是否进入真实 Top-5”，能否纠正上轮只压缩分数、反而丢失有用段落的问题。真实训练交给合作者，目前没有新的效果结果。

## 为什么做这一次

上一轮 100 题中，原 Reader、量子头、经典头选中的有用段总数为 203、147、170。量子头在训练题救回 22 个漏选直接证据，却丢失 104 个保护候选。单纯把分数差缩小到十分之一、完全不改变排序，也能让旧损失由 3.979 降至 1.065。损失下降因此不能证明筛选改善。

继承历史经验：原 Reader 排序仍是强基线；不能因为训练可微、有梯度或少数段落获救就扩大实验。先修复已经观察到的训练捷径，同时保留量子/经典和新/旧目标的交叉对照，区分训练目标改善与量子结构作用。

## 实际比较什么

| 方法 | 特征变换 | 训练目标 |
|---|---|---|
| frozen_reader_topk | 原 Reader，不训练 | 无 |
| quantum_membership | 问题条件化量子特征旋转 | 新成员资格目标 |
| classical_membership | 同参数预算经典坐标旋转 | 新成员资格目标 |
| quantum_retention_control | 同一个量子结构 | 历史保护目标 |
| classical_retention_control | 同一个经典结构 | 历史保护目标 |

新目标先按中位数/IQR 归一化分数，阻止仅靠缩小分差降损失；漏选的直接证据要越过其他 49 段中第 5 名的分数，并保留正间隔；原先已选的保护候选也接受成员资格约束。可救回数量受原来冻结的替换槽位限制。这是连续训练目标，不保证离散 Top-5 一定保持保护项，所以每轮另外统计实际救回数和保护项丢失数。

训练仍是 59 题、228 对、135 个不同漏选直接候选、183 个保守保护候选、最多 75 个替换槽位。保护候选不等于全部是直接证据。四个可训练方法均为 200 参数、3 轮、原固定顺序和超参数，不挑最好检查点。训练题与固定 100 道评价题的问题哈希不重叠；后者已经暴露，仍只能给出 L0 诊断。

复用上轮冻结 Reader 的 CLS、五组池化向量和分类头，量子模块的位置仍在分类头之前。对冻结编码器而言，这与重复提取同一特征后训练头等价，但本次没有重新加载 Reader，也不代表重放了上轮缺失的实际执行源码。

脚本从 18083 自动取得哈希固定的特征包、已完成资格审计的训练包和 100 题记录。特征包约 136 MB；缺少全部输入时合计约 171 MB，已有且哈希正确的文件复用。不下载 Wiki-DPR 或模型。默认 CPU，可选 GPU；不要求固定 Python 路径或项目安装路径。

每题保存五个方法完整 50 分数、Top-5、问题/候选身份及事后证据诊断。100 题 case study 保留问题、标准答案、全部候选文本与方法选择。本轮不调用 Generator，不生成新的回答，记录明确标注不适用。

按预注册规则，对训练/评价各前两题完整保存数值坐标；每个训练方法每轮前两步保存参数、原始/裁剪梯度、原生 AdamW 动量/步数，以及更新前后完整输出。回读时重新计算梯度并执行 AdamW 更新，不能只用已保存梯度伪造复现。另归档本次实际执行源码，独立于 Git revision。

脚本自动在 18083 创建时间戳目录、上传声明的文件并核验大小/SHA 回执。原始文本、训练目标、数值轨迹和源码压缩包只走交换服务；GitHub 仅提交每份不超过 1 MiB 的精简报告、元数据和回执。上传失败保留待上传清单并报错，不假装完成。

## 如何判定

主任务门槛沿用既定标准：量子新目标相对 Reader，每题有用段增量的均值大于零、配对 bootstrap 95% 下界大于零，直接证据均值不下降。量子归因另看是否优于同预算经典新目标。

新增训练工程门槛：固定最后一轮至少救回一个合格漏选候选，且保护候选零丢失。工程门槛失败仍如实导出全部诊断，不改训练轮数、不挑检查点、不用评价标签调参。门槛失败不扩大实验。即使本轮成功，也不是完整数据集上的 L1/L2，更不等于量子资源优势。
