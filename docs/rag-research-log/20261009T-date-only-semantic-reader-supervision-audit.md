# 先检查“训练时教给模型的好段”是不是真的好段

## 当前结论

[已测事实] 上轮训练修复成功，量子方法从203个有用证据段提升到204个，直接支持答案从138到139，只有一题改善，仍未过门。当前完成的是**给合作者的审计脚本与合成预检**，不是新一轮训练或真实数据收益实验。

## 为什么不马上再训练？

[已测事实] 原训练标签是“段落里出现答案字符串就算正例”。这是便宜的弱标签，不是专家确认的支持段。例如一个段落可能提到答案中的人名，却没有回答问题所问的事件；另一方面，真正有帮助的段落也可能用不同表达而没有原答案字符串。前一个例子是假正例风险，后一个是假负例风险；本轮尚未确定它们在434题中各有多少。

[机制解释] 如果教给模型的信号主要是字符串出现，模型可能学到普遍压低高分、抬高低分，而没有学到“这段能不能回答该题”。这与上轮看到的分数压缩相容，但还不是已经证实的失败原因。此前经典/标量控制移动得更多却没有更多好段，也说明先增加移动幅度不是最佳下一步。

## 这次具体做什么

1. 在原434个可用训练问题中固定选32题：两道原始回放见证，以及按哈希选出的30题。每题仍是相同50个候选，不重新改检索方法。
2. 完整导出题目、参考答案、50段全文、检索分数、Reader分数和名次、弱标签及触发字符串。
3. 不训练，直接重放原量子语义头、经典语义头、量子标量头。与Reader Top-5、单纯压缩Reader分数的控制一起保存各自50段分数和Top-5。
4. 保存完整数值表示和两道原始见证的隐藏层/池化追踪，验证同输入回放，避免只有一张汇总表。
5. 另导出一份盲审JSON：打乱段落顺序、隐藏分数/排序/弱标签/方法名称。各段支持判断留空；回收后先独立判断，再与数值连接分析。

这样可以分清两件事：**训练标签是否教错了；训练标签即便没错，量子头有没有真的把好段相对坏段拉开。** 所有字符串计数都明确标为弱标签计数，不会冒充选段正确率。

## 边界、对照和留出验证

- 32题每题50段，共1600段；五个评分/筛选视图共享同一批输入。
- 只调用已冻结的Reader和旧检查点，不调用Generator或答案评测器，不更新参数。
- 100题Silver不进入这个导出；只用100个问题哈希排除重叠。参考答案来自训练集，用于观察现有弱标签，不是新的在线评分输入。
- 预先登记原434题未来的347/87训练/验证分区。但**旧头已经训练过这两个分区**，本次回放不能称为未见题验证。该分区只有未来重新初始化训练时才发挥留出作用。
- 重点比较高分弱负例、靠近Top-5门槛的弱正例、深处弱正例与同名次带的弱负例控制。成组候选计数相关，不能当作独立题目统计显著性。
- 原430多条输入的全文哈希此前没有保存。本次检查ID/顺序/弱标签一致，并验证两道旧输入的数值表示；不宣称其余全文已经与历史逐字比较。

## 结合累计经验，下一步怎么选

唯一推荐路径：**先完成这32题的支持盲审与边界判别诊断，再决定量子训练目标。** 保留Reader锚点、问题条件化语义表示和已修好的优化流程；不重复宽泛span融合、通用多样性替换、盲目增加残差或加深线路。

- 假设：正确的支持关系监督与筛选边界配对能避免“泛化压分”，让量子语义交互学习选择性的纠错。
- 最小下一步：合作者导出32题，本对话独立审阅原文后连接评分；区分标签错、可达幅度不足、支持信号不分离。
- 成功门：真实输入/回放/回执通过，能给出可核验的支持关系案例及成组对照；不是要求弱标签命中数上升。
- 停止门：身份、缓存或trace不合格则修复；支持监督不足则先修监督，不直接扩大旧训练配置。
- 资源：32次缓存检索、1600个Reader候选前向、旧小头重放；没有训练预算。审阅仍是诊断，不自动变成可信gold。
- 授权：本次导出和实现已获用户同意；新的训练机制与真实训练运行尚未自动获批。
