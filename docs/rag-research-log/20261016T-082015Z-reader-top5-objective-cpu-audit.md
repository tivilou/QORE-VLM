# 先修训练目标：稳健归一化与真实 Top-5 边界检查

本轮完成代码和 CPU 审计，没有重训量子头，也没有产生新的100题筛选结果。它解决的是上一轮“损失下降却大量丢失好段”的一个已证实漏洞；是否能提高筛选效果，需要随后独立命名、预注册的量子/经典成对训练检验。

## 为什么先做这一步

上一轮量子旋转头并非完全没有学习：训练集中救回22个合格漏选正例，但丢掉104个受保护段，得不偿失。仅把全部分数缩小到10%，排名完全不变，旧目标也能从3.979降至1.065。这说明优化器有办法完成数值目标而不完成筛选目标，但不能据此断言所有错误都由分数压缩造成。

结合之前 span 固定融合、Q-ARCG 和语义残差的经验，下一步仍保留 Reader 的问题条件语义输入、Reader 内量子旋转和同预算经典对照，不继续盲目加大残差、线路或训练轮数。先让目标函数奖励“真正跨过第五名且保住已有证据”，而不是奖励缩小分差。

## 实现

新增 `applications/rag/scale_invariant_top5_objective.py`，只接收训练分数、原始分数和冻结训练资格，不用于线上挑段。

1. 每题50个分数先减中位数，再除以四分位距换算的尺度。尺度参与求导，不使用可奖励整体收缩的固定 epsilon；尺度塌缩直接报错。正常数值范围内，正比例压缩、放大和统一平移不改变目标。
2. 对每个待救援/受保护段，用其余49段的第五高分作为实际入选边界，并保留正 margin。不能用段落自己的分数作为边界，也不能把打平视为救回。
3. 每题只推动最多可替换槽位数的合格正例，不要求135个正例全部挤进总共75个可用位置。183个保守受保护段全部保留保护项；这些段并非全部是直接正例。
4. 归一化后保留对原 Reader 分数的锚定项。平滑保护项仍不保证离散 Top-5 留存，因此实际救回数和丢失数必须单独审查。

开发中发现标准差归一化也不够：把一个无关低分段继续压低，可以撑大标准差并让真实边界看起来更小。最终采用中位数/四分位距，并将这个反例加入合成测试和59题缓存审计。这只说明已覆盖该反例，不是对所有潜在目标捷径的数学排除。

同时修复原 runner 的三项交付问题：损失函数按方法名的 loss 后缀独立分派、解包 `row["target"]`、补齐训练包64位 SHA256。新增声明源码的执行前归档和执行后哈希检查，五个训练分支均记录实际目标函数名；若使用项目内其他配置路径，归档和 provenance 跟随实际配置。修复不回写历史结果，也不能补回上一轮缺失的实际执行源码。

**新损失没有接入已关闭的100题 runner。** 该 runner 的旧/新损失命名仍指历史两种定义；不能直接运行它来声称在测试本轮目标。

## 审计结果

固定输入仍为59题、228对、135个合格漏选正例、183个保守受保护段、75个最大替换槽位。只访问训练记录；没有读取100题的评估指标、Silver 判定，也没有改变任何选段输出。

本地及已验证的主服务器各通过21项单元测试，包括损失分支反例、真实目标包装接口、量子/经典合成头梯度、实际配置纳入归档和源码归档回读。合成接口测试只有一次随机数据更新，不是真实训练。

两地缓存审计完全一致：708次正仿射变换检查，最大分项差异9.72e-12；177次常量塌缩拒绝；59次极低分离群点检查；保存24个数值数组，重新打开后独立重算6组分数梯度。没有模型/优化器参数更新。

| 历史分数来源 | 候选目标均值 | 旧目标均值 | 已有救回数 | 已有受保护段丢失数 |
| --- | ---: | ---: | ---: | ---: |
| 冻结 Reader | 1.566728 | 3.979397 | 0 | 0 |
| 上轮量子头 | 2.085252 | 1.177091 | 22 | 104 |
| 上轮经典头 | 1.720377 | 1.179057 | 28 | 78 |

新目标不再把上一轮差的量子检查点评价为比 Reader 更低损失，但这只是目标与已知问题的相容性检查。两列目标定义不同，不能跨列比较大小，也不能据此声称重新训练后会有收益。

本地：Python3.11.0、Torch2.3.1 CPU、NumPy1.23.5，复用 lambeq。服务器：Python3.10.12、Torch2.7.1、NumPy1.26.4，显式 CPU。没有安装依赖、加载 Reader、下载 Wiki-DPR 或调用 GPU。

## 下一步与停止条件

下一步是为该候选目标建立独立的量子/经典成对训练 contract 和 runner：保持原训练资格、Reader、线路容量及预算，记录实际 Top-5 救回/保护损失，并补齐优化器状态与更新回读。不能把本轮通过解释为新实验已准备好交给合作者；当前 manifest 明确为 `formal_training_ready: false`。

若真实训练只降低损失、无法在保护已有证据的同时救回合格漏选段，则停止扩大这组目标/头配置。后续固定100题仍只是暴露面板 L0，完整真实数据上的独立收益才支持更高证据等级；量子归因另需胜过匹配经典对照。训练目标修复本身不构成量子贡献。

这一步不需要 GPU。未来重新提取 Reader 隐状态适合使用 GPU；复用已缓存特征时，小量子/经典头及目标检查可在 CPU 上完成。
